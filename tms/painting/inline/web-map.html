Non-geographic image map, declared inline in a <map is="web-map">

The same painting and the same linked figures, hosted by the customized built-in <map>. A picture with clickable regions in it is what <map> has always been for; the difference is that these regions are content — named, focusable, and still there when the image is zoomed.

MapML.js (Leaflet)

The <map> hosts its chrome on a child <div class="mapml-web-map">; the layers and their linked features are the author's markup either way.

MapML-MapLibre

Two reasons at once: MapLibre renders Web Mercator only, so the WGS84 painting is unsupported, and in WebKit the customized built-in <map> never upgrades either.

Worth comparing with the <area>-based image map in Progressive enhancement, which is what a browser is left with when the element does not upgrade.

MapML-OpenLayers

One viewer implementation serves both root elements, so the fragment links, the per-zoom feature swap and the link styling behave identically to the <mapml-viewer> frame.

An image map made of <area> elements stops being true the moment the image is scaled or panned, because its coordinates are pixels of a particular rendering. These figures are in the painting's own coordinate system, so they survive zooming — and the two versions of the girl show that the author can change the answer by scale.

A GeoJSON file handler, as a progressive web app

A map page that the operating system can open .geojson files with. Each frame below is an installable web app: its manifest declares a file_handlers entry for application/geo+json, and a file opened with it arrives through launchQueue, is turned into a <map-layer> by the viewer's geojson2mapml(), and is zoomed to. The map is inside a shadow root, as it would be in an app built from custom elements.

What to try

  • Load a GeoJSON file with the button above a map, for example canada.geojson, example2.geojson or cph-example1.geojson. Click a feature to see the properties the page gave it.
  • To use it as a file handler, open a frame with its Open full page link, in a desktop browser that supports file handlers, and install it. A .geojson file's Open with menu then lists the app, which opens with ?log=y and shows an activity log under the map.
  • Go fullscreen and back. The fullscreen element is the viewer, inside <main-app>'s shadow root, where document.fullscreenElement reports <main-app> instead; a viewer that relies on it can enter fullscreen but not leave it.
  • Search for a place: the layer's <map-link rel="search"> and rel="suggestions" point at Photon, and each implementation's default handling lists the results and moves the map.

Why each frame is its own app rather than this page being one: launchQueue hands files only to the top-level page of an installed app, never to an iframe. The six frames (three implementations, two root elements) link six manifests with different ids; each <map is="web-map"> app's scope is its own page, nested inside the folder scope of the <mapml-viewer> app beside it, so each page opens in its own app. The shadow root is declarative, <template shadowrootmode="open">, so the code panel shows the map markup as written; the page's styles stop at the shadow root, which is why it carries its own small <style>.

Experiments

Feature index, over features fetched as MapML

The page names a document — <map-layer src="restaurants.mapml"> — and the eight features arrive after the map has drawn, into a shadow root the page never sees. The index has to notice them there and start naming them, with no second prompt from the reader: the first thing a screen reader user hears about this map is produced by content that was not in the page when it loaded.

MapML.js (Leaflet)

The layer is named in the control by the document's own <map-title>, and the licence link is the document's too — attribution travels with the data, and so do the captions the index reads.

MapML-MapLibre

Remote MapML is parsed as XHTML, so the boolean attributes are spelled out in full — checked="checked" — and a malformed document is a fatal error rather than something the parser quietly repairs.

MapML-OpenLayers

A fetched layer keeps its content in a shadow root, which is exactly the boundary a :scope > selector does not cross. Several features of the port have gone missing there without the map looking any different; the index says so out loud.

Trying it

Each map starts static. Release the lock with the lock button to pan, and the list under the reticle is re-read after each move; pan or zoom out and more of the eight restaurants fall inside the box. The MapML.js frame lists nothing at all until the lock is released and the map is focused: its index waits for focus, and static turns off the handler that makes the map focusable.

Press 1–7 to open a listed feature, 9 for the next page when more than seven are covered and 8 to go back, and Escape to close a popup.

Only the restaurant layer is worth serving remotely for the purposes of this experiment; the basemap is the shared osm.mapml in both variants, because it is hidden and carries nothing for the index to find.

Feature index in a <map is="web-map">, over features fetched as MapML

Two shadow roots now stand between the page and the captions being read: the fetched layer's, and the one the map chrome is built in because an <map> cannot host its own. The reader should not be able to tell — the same reticle, the same numbered list, the same keys.

MapML.js (Leaflet)

The reference implementation, by way of its second copy of the viewer. Everything the index needs — the fetched captions, the reticle, the live region — has to be present in both copies.

MapML-MapLibre

Customized built-in elements are not implemented in WebKit, so in Safari this frame stays an inert <map>. Elsewhere it is the map beside it.

MapML-OpenLayers

The viewer is a mixin shared by both root elements, so the overlay is written once and reads the map's render root rather than assuming the element has a shadowRoot of its own.

Release the lock before panning — and before expecting the MapML.js frame to say anything, since its index waits for the map to be focused and static turns off the handler that makes it focusable.

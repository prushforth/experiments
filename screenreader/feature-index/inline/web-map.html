Feature index in a <map is="web-map">, over features declared inline

The same eight restaurants and the same reticle, hosted by the customized built-in <map is="web-map">. A reader who has turned the index on has turned it on for every map, whichever element it happens to be written as — so the overlay has to find its way into a root element that cannot even host its own shadow root.

MapML.js (Leaflet)

web-map.js is a second copy of the viewer upstream, so the index is switched on by a second copy of the same code — a duplication that is invisible until one half of it falls behind the other.

MapML-MapLibre

Customized built-in elements are not implemented in WebKit, so in Safari this frame stays an inert <map>. Elsewhere it is the map beside it.

MapML-OpenLayers

One viewer serves both root elements here: the chrome, including the reticle and the live region, is built on a child <div class="mapml-web-map"> because an <map> cannot host a shadow root, and nothing above that seam knows the difference.

Release the lock before panning, as on the <mapml-viewer> page — and before expecting the MapML.js frame to say anything, since its index waits for the map to be focused and static turns off the handler that makes it focusable.

Experiments

Feature index, over features declared inline

Eight restaurants written in the page, and a reticle at the centre of each map naming the ones it covers. The list is a live region, so it is re-read on every move; the number beside a caption is the key that opens that feature. Nothing in the map markup asks for any of this — the index is switched on by a <map-options> preference, and what it can say is decided entirely by whether the features have <map-featurecaption>s worth reading.

MapML.js (Leaflet)

The reference implementation, and the only one where the preference is the whole interface: MapML.js has no control for the index, so a page either gets it from the reader's settings or not at all. Its index is also focus-gated — nothing is listed until the map is focused — and static turns off the very handler that makes the map focusable, so this frame stays silent until the lock is released.

MapML-MapLibre

MapLibre added an optional megaphone control (controlslist="featureindex") for readers who want the index on one map rather than all of them. It is not used here, so that the three frames are switched on the same way.

MapML-OpenLayers

Features are drawn to a canvas, so the index cannot be read off the document: it is computed from the view extent each time the map settles, and the numbered keys are bound to the map viewport rather than to any feature.

Trying it

Each map starts static, so scrolling past it does not zoom it. Two of the three frames are already listing whatever the reticle covers; MapML.js is not, for the reason above. Release the lock with the lock button, click or Tab into the map, and all three agree. Pan, or zoom out, and more of the eight restaurants fall inside the box.

With the keyboard alone: Tab to a map, release the lock, then use the arrow keys to pan. The list is re-read after each move. Press 1–7 to open a listed feature, 9 for the next page when more than seven are covered and 8 to go back, and Escape to close a popup.

Turn the preference off — remove the <map-options> script from the framed page — and the maps are unchanged in every other respect. That is the point: the index is the reader's, not the author's, and it has nothing to work with that a pointer user was not already given.

Feature index

A sighted reader finds out what is in the middle of a map by looking at it. The feature index answers the same question out loud: a reticle is drawn at the map's centre, and a live region lists the <map-featurecaption> of every feature the reticle touches, numbered, so that pressing 1–7 opens one. Pan, and the list is spoken again. It is the piece that turns panning from a gesture into a query — and it is not author markup at all, but a user preference the reader turns on, which is why every map on this site has to behave well when it appears.

The preference is the same in all four cells and in all three implementations: a <map-options> element carrying {"featureIndexOverlayOption":true}, appended to <head> from script because that is how the MapML browser extension injects it. No map on these pages asks for the index; the reader does.

The content type is the restaurant layer's. Inline, its eight <map-feature> elements are children of the page. Remote, they are children of a document the layer fetches and keeps in a shadow root — and the index has to find them there, after the map has already loaded, which is a different code path in every implementation and the one worth watching.

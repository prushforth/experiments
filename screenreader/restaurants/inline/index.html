Experiments

Restaurant locations in Ottawa, declared inline

The restaurant layer is written in the page: a <map-select> naming the cuisine variable, and a <map-link rel="features"> whose tref spends it. Tab into a map and the features are reachable one by one; each announces its <map-featurecaption>, and Enter opens the properties table. Change the cuisine in the layer control and the template is re-requested — the same interaction, from the keyboard, that a pointer user gets from the <select>.

MapML.js (Leaflet)

The reference implementation. Each feature is an SVG <g> in the document, so the focus order, the accessible name and the popup are the browser's own — the map is a document, not a picture of one.

MapML-MapLibre

MapLibre draws to a canvas, so the tab stops are a parallel layer of focusable elements the renderer keeps in step with what is on screen. What the reader hears should not give that away.

MapML-OpenLayers

Also a canvas renderer, and also a proxy per in-view feature: one tab stop takes you into the features, the arrow keys move between them nearest-first, and Escape returns to the map.

Trying it

Each map starts static, so scrolling past it does not zoom it — release it with the lock button before using the keyboard, which is otherwise held too.

With the keyboard alone: Tab to a map, Tab again to reach the features, arrow between them, Enter for the properties, Escape back to the map, then Tab on to the layer control and its cuisine <select>. Nothing here needs a pointer, and nothing needs the page's script.

The basemap layer carries hidden, so it never appears in the layer control: it is scenery, not a choice, and a reader tabbing through the control should not have to dismiss it. Its <map-extent> is hidden too.

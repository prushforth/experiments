Experiments

Restaurant locations in Ottawa, declared inline in a <map is="web-map">

The same layers, the same cuisine filter, hosted by the customized built-in <map is="web-map"> instead of <mapml-viewer>. The root element is the one part of this the reader should never notice: the features are the same tab stops with the same names, and the layer control is the same set of form controls.

MapML.js (Leaflet)

An <map> cannot host a shadow root, so the map chrome is built on a child <div class="mapml-web-map">. The features and the layer control are otherwise identical to the <mapml-viewer> page.

MapML-MapLibre

Customized built-in elements are not implemented in WebKit, so in Safari this frame stays an inert <map> and the note is the only thing to read. Elsewhere it is the same map as the frame beside it.

MapML-OpenLayers

One implementation of the viewer serves both root elements here, so <map is="web-map"> gets the feature tab stops, the <map-select> and the rest without a second code path to keep accessible.

<map> is a known element, so a browser that does not upgrade it still renders its contents' fallback rather than nothing — which is the subject of Progressive enhancement / graceful degradation. Here the point is narrower: the accessibility of the map must not depend on which element hosts it.

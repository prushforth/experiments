Restaurant locations in Ottawa, from remote MapML documents

The page names two documents and nothing else: <map-layer src="restaurants.mapml"> and the basemap beside it. The cuisine <map-select>, the <map-link rel="features"> template and the layer's own title all arrive from the server, and the layer keeps them in its shadow root — so the layer control has to reach across that boundary to build the same form controls, and the features have to become the same tab stops, as when the markup is in the page.

MapML.js (Leaflet)

The layer is named in the control by the document's own <map-title>, and its licence link is the document's, not the page's — attribution travels with the data.

MapML-MapLibre

Remote MapML is parsed as XHTML, so the boolean attributes are spelled out in full — checked="checked", selected="selected" — and a malformed document is a fatal error rather than something the parser repairs.

MapML-OpenLayers

The tref in the fetched document is relative to that document, not to this page, which is what lets the same restaurants.mapml be served from anywhere and still find its feature documents.

Only the restaurant layer is worth serving remotely for the purposes of this experiment; the basemap is a shared document (osm.mapml) in both variants, because it is hidden and there is nothing in it for a reader to reach.

The feature documents themselves — african.mapml and the rest — are remote in both content types: what rel="features" fetches is always a document. The axis on this page is whether the layer is one too.

Restaurant locations in Ottawa, remote MapML in a <map is="web-map">

The same two <map-layer src> declarations, hosted by the customized built-in <map>. These frames load the very same restaurants.mapml as the <mapml-viewer> page beside them — a MapML document says nothing about the element that will host it, which is why the root element is a variant of the page and not of the data.

MapML.js (Leaflet)

Two shadow roots are in play: the one the <map> puts its chrome in, and the one each layer keeps its fetched document in. Neither should be visible in the reading order.

MapML-MapLibre

In WebKit, where customized built-ins are not implemented, this frame stays an inert <map> — and because the layers are remote, there is not even markup in the page to fall back to.

MapML-OpenLayers

The viewer is one implementation shared by both root elements, so the <map-select> that has to be found inside the layer's shadow root is found the same way here as in the <mapml-viewer> frame.

This is the cell with the least markup in the page and the most work for the implementation: an element the browser only partly understands, hosting layers whose content it has not fetched yet. If the features are still tab stops with names and the cuisine filter is still a <select>, the accessibility of MapML is in the vocabulary rather than in any one way of writing it down.

Restaurant locations near Dows Lake, from remote MapML

The same search and the same runtime layer, except that the restaurant layer in the <template> is one line — <map-layer src="restaurants.mapml"> — and everything else about it arrives from the server when the reader asks for it. Appending a layer and fetching a layer now happen in that order, so the tab stops appear a moment after the button is pressed rather than with it.

MapML.js (Leaflet)

Two layers arrive from documents here — the basemap and the restaurants — and one is built in the browser from GeoJSON. All three end up as the same kind of thing in the layer control.

MapML-MapLibre

The fetched document names itself with <map-title>, which is why the template does not have to carry a label: a remote layer knows what it is called.

MapML-OpenLayers

The tref inside restaurants.mapml is relative to that document, so the cuisine documents are found from wherever the layer is served — not from wherever it happens to be used.

A layer that is a URL is a layer a page can offer without knowing anything about it. That is the interesting part of the remote variant here: the page's only claim about the restaurants is where to get them, and it still has to be true that what comes back is reachable by keyboard and named for a screen reader.

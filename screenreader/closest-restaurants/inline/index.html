Restaurant locations near Dows Lake, declared inline

Search for a place — Dows Lake, say — choose it from the results, and the map goes there with the place drawn on it. Then ask for the restaurants: a <map-layer> written inline in a <template> is cloned into the map, and its <map-link rel="features"> fetches whatever falls inside the view. Nothing on this page is a picture of a map: the place arrives as GeoJSON and becomes <map-feature> elements through M.geojson2mapml(), and both layers are reachable from the keyboard the moment they are appended.

MapML.js (Leaflet)

The reference implementation of both halves of this: geojson2mapml and the runtime appendChild of a whole layer, which has to build its features, its layer control entry and its tab stops after the map is already up.

MapML-MapLibre

Watch what zoomTo() does to a single point: a point has no area, so what counts as "close enough" is a decision each implementation has to make, and the answer decides what the reader finds nearby.

MapML-OpenLayers

The restaurant layer's <map-extent> is hidden, so its cuisine <map-select> stays out of the layer control here — the layer is meant to answer one question, not to be configured.

Trying it

Each map starts static, so scrolling past it does not zoom it. The search still moves it; the lock button releases it for panning and zooming by hand, keyboard included.

From the keyboard: Tab to the search box, type a place name, Enter, then Tab into the results and Enter on one. Focus moves to the map, so the next Tab is into the features. Come back out, press Add restaurants, and the features you can tab through now include whatever is near the place you chose.

The search itself is ordinary page script over the NRCan GeoNames service; the only map-specific calls are M.geojson2mapml(), layer.zoomTo() and map.appendChild(). Everything the reader hears comes from the vocabulary, not from the script.

Restaurant locations near Dows Lake, declared inline in a <map is="web-map">

The same search, the same two layers added at runtime, hosted by the customized built-in <map>. The page script does not know which element it has: it finds the map with a selector that matches both, and then talks to it entirely through the DOM — appendChild, zoomTo, focus.

MapML.js (Leaflet)

A layer appended to a <map> ends up beside the <div class="mapml-web-map"> that hosts the chrome, not inside it — the element the script appends to is still the one the author wrote.

MapML-MapLibre

In WebKit, where customized built-ins are not implemented, the <map> never upgrades: the search box is still there and still works, but it has nothing to talk to.

MapML-OpenLayers

Both root elements share one viewer implementation here, so geojson2mapml and the feature tab stops are the same code in this frame as in the <mapml-viewer> one.

A script that drives a map should not have to know how the map was declared. The selector mapml-viewer, map[is="web-map"] is the whole of this page's accommodation for two root elements; everything after it is the same DOM API.

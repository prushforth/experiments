Announce zoom, declared inline in a <map is="web-map">

The same announcements, hosted by the customized built-in <map>. Worth its own page because the live region has to live somewhere: a <map> cannot have a shadow root of its own, so the viewer builds its chrome — and its <output> — on a child element instead. If the announcements still arrive, that detail has stayed where it belongs.

MapML.js (Leaflet)

The <output> ends up inside the <div class="mapml-web-map"> the map builds for itself, which is still inside the <map> the author wrote.

MapML-MapLibre

Customized built-ins are not implemented in WebKit, so in Safari this frame stays an inert <map>: no map, and nothing to announce about it.

MapML-OpenLayers

One viewer implementation serves both root elements, and the announcement handler asks it for its render root rather than assuming a shadow root — which is exactly the bug this page would catch.

The basemap is scenery — its <map-extent> is hidden and the layer control is off — but it is not only scenery: the <map-link rel="search"> and <map-link rel="suggestions"> declared on it are what give the search box somewhere to ask. The remote variant moves that declaration into the layer's own document.

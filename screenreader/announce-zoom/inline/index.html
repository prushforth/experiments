Experiments

Announce zoom, declared inline

A map that says where it has got to. With <map-options>{"announceMovement": true}</map-options> the viewer keeps a visually hidden <output role="status"> and writes into it whenever the map settles: the new zoom level, or which edge of the content you have run off. A sighted user reads the map; a screen reader user is told the same thing in words, which is otherwise the part of panning and zooming that simply does not arrive.

Content type Inline Remote
Root element <mapml-viewer> <map is="web-map">

MapML.js (Leaflet)

The reference implementation: a Leaflet handler on the map's own moveend, which is why the announcement comes after the move rather than with every frame of it.

MapML-MapLibre

The live region is part of the viewer, not of the renderer, so the wording comes from the same localized strings in all three — what differs is only which event the renderer calls "settled".

MapML-OpenLayers

OpenLayers can settle on a fractional zoom, so the announcement rounds before it speaks: "zoom level 11.4" would be true and useless.

What to try

  • Turn on a screen reader, Tab into a map, and zoom with + and − or the buttons. Each settled zoom is announced once.
  • Without a screen reader, the same text is in the DOM: the first <output> in the map's shadow root reads zoom level 12 and so on. Browser accessibility inspectors show it as a status live region.
  • Focus the map and listen for its name — <map-caption>Paris, the City of Light</map-caption> is what makes the map a named thing rather than "graphic".
  • Search for somewhere and pick a result. Being moved somewhere you did not pan to is the case where an announcement matters most, and it is the reason this page declares <map-link rel="search"> and <map-link rel="suggestions"> on its layer: the search box is drawn by controlslist="search", but it has somewhere to ask only because the layer says where.

The results list and the move to the chosen place are the implementations' own default handling of mapsearch / mapsuggestions. No page script is involved; an author who wants their own results UI calls preventDefault() on those events and renders event.detail.responses instead.

<map-options> is not part of the MapML vocabulary; it is how these implementations let a page set M.options before the map is built. It has to be created by script and appended to <head>, because the HTML parser moves unknown elements written in <head> out into the body — where the viewer does not look for it. A standard version of this would more likely be a preference the user sets than a switch the author flips.

Announce zoom, from remote MapML

The page now says only <map-layer src="osm.mapml">. The tiles, the licence and the search service come from that document: it declares <map-link rel="search"> and <map-link rel="suggestions"> in its own <map-head>, so a layer arrives knowing how it can be searched. The page contributes the search box by asking for it — controlslist="search" — and the announcements that follow being moved somewhere.

MapML.js (Leaflet)

The search control looks for rel="search" across the map's layers, so it finds the fetched document's links in the layer's shadow root exactly as it finds a page's own.

MapML-MapLibre

A layer that is hidden from the layer control still contributes its search links: being out of the control is about what the reader can switch, not about what the layer offers.

MapML-OpenLayers

The search box appears only once the document has been fetched and its links found — a control whose existence depends on content that has not arrived yet.

A search service travelling with the layer is the part worth arguing about: the page did not choose Photon, and does not name it. Had this document come from a national mapping agency it would have named that agency's gazetteer, and the same page would have searched it, in the same box, announcing the same way.

The results list and the move to the chosen place are the implementations' own default handling of mapsearch / mapsuggestions, not page script.

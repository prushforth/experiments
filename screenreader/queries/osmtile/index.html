Fire danger queries, in Web Mercator

A forecast of fire danger across Canada, drawn by a WMS and queried through the same service's GetFeatureInfo. Click the map, or focus it and press Enter or Space to query its centre: the answer opens in a popup, focus moves into it, and a screen reader reads the forecast value for that place.

MapML.js (Leaflet)

The reference implementation. A query from the keyboard is aimed at the map's centre, the same point the reticle marks for the feature index, so a reader who pans with the arrow keys can ask about wherever they have arrived.

MapML-MapLibre

The popup is titled Feature, which the other two leave out. MapLibre fetches its tiles rather than loading them as images, so the basemap must come from a server that allows cross-origin requests; the others would draw it regardless.

MapML-OpenLayers

Tab rests focus on the viewer itself rather than on a map container inside it, so the keyboard query listens there. As in MapML.js, it fires only when the map has focus, not a control or popup inside it, so the Enter that presses a popup button does not start another query.

Trying it

Tab to a map and press Enter. The maps start static, which stops them moving but not answering queries. Focus moves to the popup, which reads a table of one property, FDR, the forecast fire danger rating at the map's centre. Escape closes it and returns focus to the map. Release the lock to pan with the arrow keys and query somewhere else.

Query outside the forecast area — over Hudson Bay, say — and the service does not say no data: it answers with its no-data value, -3.4028234663852886e+38, and all three implementations read it out as is. A sighted user sees there is no colour there; a screen reader user hears a number with seventeen significant digits and an exponent.

The basemap layer is hidden, so the layer control lists only the fire danger layer. Its name links to the legend (<map-link rel="legend">), which is where the colours are explained.

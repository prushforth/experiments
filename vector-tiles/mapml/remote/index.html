MapML vector tiles from remote layer documents

The same tiles and the same stylesheet as the inline version, but each layer is now a MapML document of its own, named by <map-layer src> and parsed as XHTML. The layer's name in the layer control comes from the document's <map-title>, and every href and tref in it resolves against the document, not against this page.

MapML.js (Leaflet)

Two documents, one per projection, each offering the other as <map-link rel="alternate">: put either one in a map of the other projection and the layer follows the map.

MapML-MapLibre

The renderer is Mercator only, so the WorldCRS84Quad map falls back to OSMTILE — which is exactly what the WGS84 document's rel="alternate" link is for. Feature colours still need <map-link rel="stylesheet">, which is not implemented there yet.

MapML-OpenLayers

The stylesheet arrives in the fetched document's <map-head> and has to reach the sub-layer each tile's features are rendered into — the same CSS-through-a-probe path as the inline version, one shadow root further away.

Publishing the layer as a document is what makes projection negotiation possible: the alternate is a link, so the client can pick the representation that suits its map before anything is drawn.

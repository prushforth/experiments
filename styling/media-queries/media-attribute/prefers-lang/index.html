Choosing map content by prefers-lang, with media

Three basemaps, one per outcome: the Canada Base Map labelled in English, the same map labelled in French, and OpenStreetMap for everyone else — each gated by <map-layer media="(prefers-lang: …)">. Which one you get depends on the language you have asked your browser for, not on anything this page does.

Mechanism media attribute matchMedia() API

Variants Inline only <mapml-viewer> only

MapML.js (Leaflet)

The reference implementation. The layer control holds one entry — the layers that do not match are absent, not disabled.

MapML-MapLibre

The same three declarations. Nothing about this feature is renderer-specific: the decision is made before any tile is requested.

MapML-OpenLayers

The layer's own lang and <map-title> are in the matching language too, so the layer control reads correctly as well as the map.

The three outcomes

Changing your preferred language

  • Chrome: chrome://settings/languages — add languages in order of preference and set the first one to a language and locale, then restart.
  • Firefox: about:preferences → Language → Choose…, beside “Choose your preferred language for displaying pages”.
  • Edge: edge://settings/languages — add languages and restart for the setting to take effect.

prefers-lang is under review, and this page is as much the record of the question as of the answer: HTTP and HTML already have a mechanism for choosing a representation by language — hreflang, and content negotiation behind it — and a language is arguably not a property of the medium at all. The experiment stays because the shape of it is right whatever the feature ends up being called.

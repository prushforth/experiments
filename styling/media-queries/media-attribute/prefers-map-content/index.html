prefers-map-content, with media

A reader may want a map made of features they can tab through, or of tiles that draw quickly, or of one big image, or not a map at all but a table. One dataset, published every way, and the query written on the element that offers each one — so the ones that do not apply are never fetched.

Mechanism media attribute matchMedia() API

Where the query goes

  • On <map-layer> — five remote documents, one per representation, each its own entry in the layer control.
  • On <map-link> — one layer whose templated links offer the same data several ways, so the layer keeps one identity.

The assets are shared by both: canada.xml (the features), legend_query_msi-94-plus.mapml (the query response) and msi-tables/, which holds a description table per year of the time <map-select> — the “table” representation itself, and the one preference no map element can carry.

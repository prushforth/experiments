Choosing a templated link by prefers-map-content, with media

One layer, one <map-extent>, and a <map-link media> per representation: a WMS GetMap image, the same request tiled, or features. Press the preference buttons and the templates come and go while the layer keeps its identity — and its year — in the layer control.

MapML.js (Leaflet)

The reference implementation. The time <map-select> belongs to the extent, not to any one template, so the year survives a change of representation.

MapML-MapLibre

A non-matching template contributes nothing to the extent's bounds, so the layer's reported extent follows the preference as well as its drawing does.

This dataset is published in CBMTILE, which MapLibre cannot render; it warns and falls back to Web Mercator.

MapML-OpenLayers

Enabling a link rebuilds its template variables and its sub-layer from scratch, which is what lets the tiled and untiled forms of the same WMS request share one extent without interfering.

This is the finest granularity the declarative form reaches, and the one a service would publish: the layer is a thing the reader can turn on and off, and the media queries decide only how it is drawn. Gating whole layers instead makes each representation a separate entry in the layer control, which is right when they really are separate products.

Tables remains the preference with nowhere to live: the original experiment left a <map-link rel=""> commented out because no rel describes “a table instead of a map”. The handler on this page substitutes the year's description table, which is the honest admission that this one is still an open question.

The script version does the same work for every preference, not just that one.

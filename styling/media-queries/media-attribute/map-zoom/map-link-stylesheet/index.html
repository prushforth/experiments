Styling a feature by map-zoom, with media

Eighteen stylesheets, one per zoom level, each attached with <map-link rel="stylesheet" media="(map-zoom: n)">. Zoom the map and the point changes hue — the same result as the matchMedia() version, with no script at all, because the user agent applies the stylesheet whose query matches and ignores the rest.

Mechanism media attribute matchMedia() API

Variants Inline only <mapml-viewer> only Gated element: <map-link rel="stylesheet">

MapML.js (Leaflet)

The reference implementation. A non-matching stylesheet link is disabled, so its rules are not in the cascade and the file behind it is not requested.

MapML-MapLibre

The author's CSS is compiled to MapLibre paint properties, so enabling a different stylesheet recompiles the layer's style rather than re-running the cascade.

MapML-OpenLayers

The enabled stylesheets are injected into a hidden container holding one probe element per feature, so the colour that wins is the one the real CSS cascade picks, read back with getComputedStyle.

Eighteen files to say what one script says in four lines is the honest cost of the declarative form; what it buys is that the map is correctly styled before any script has run, and that a zoom level nobody visits costs nothing. The script version makes the opposite trade.

The stylesheets (1.css … 18.css) sit one folder up from the framed pages and are shared by all three implementations — their contents are plain CSS against the feature's class, and nothing in them is implementation-specific.

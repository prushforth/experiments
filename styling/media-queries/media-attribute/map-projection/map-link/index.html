Choosing a tile template by map-projection, with media

The same experiment as the <map-layer> version, one level finer: a single layer holds a <map-extent> per projection, and it is the <map-link rel="tile"> templates inside them that carry media="(map-projection: …)". The layer stays put in the layer control while the tiles behind it change.

Mechanism media attribute matchMedia() API
Gated element <map-layer> <map-link>

Variants Inline only <mapml-viewer> only

MapML.js (Leaflet)

The reference implementation. The layer control shows one entry throughout, because the layer never stops matching — only its templates do.

MapML-MapLibre

A disabled template is removed from the extent's bounds as well as from the map, so the layer's reported extent follows the projection too.

MapML-OpenLayers

Each template owns a tile grid built for its projection, so the gate decides which grid exists — the wrong one would otherwise request Web Mercator tiles at Lambert coordinates.

This is the shape a service publishing the same basemap in two projections would naturally produce: one layer, one identity in the layer control, and a template per projection. The <map-layer> version moves the decision up a level, which is the right answer when the two projections are genuinely different products rather than two renderings of one.

Both are declarative. The script version shows what has to be written by hand to get the same result.

Choosing a data source by map-projection, with media

Two <map-layer> elements over the same basemap, one per projection, each carrying media="(map-projection: …)". The buttons change the viewer's projection and the user agent does the rest: the layer that cannot be drawn is absent from the map, absent from the layer control, and its tiles are never requested.

Mechanism media attribute matchMedia() API
Gated element <map-layer> <map-link>

Variants Inline only <mapml-viewer> only

MapML.js (Leaflet)

The reference implementation. Watch the layer control: it holds one entry at a time, because the non-matching layer is not merely disabled but absent.

MapML-MapLibre

MapLibre is natively Web Mercator, so the Lambert button asks more of this implementation than of the other two.

MapML-OpenLayers

An OpenLayers View has an immutable projection, so changing it builds a new view and re-attaches every layer; the media attribute is re-evaluated as part of that.

The script version of this experiment reaches the same end state by hand, toggling hidden and checked from a change handler. The difference shows up in what happens before that handler runs, and in what happens if it never does.

Gating the whole layer is the blunt version: the <map-link> variant keeps one layer and gates the individual tile templates inside it, which is what a service offering the same data in two projections would naturally publish.

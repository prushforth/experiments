Choosing a data source by map-projection, with matchMedia()

Maps come in many projections, and a web map can change between them — but a tile collection cannot. The buttons set the viewer's projection; a (map-projection: OSMTILE) matcher notices, and its change handler swaps the map onto the <map-layer> whose tiles exist in the projection the map is now in. Without that, the layer that cannot be drawn would simply go disabled and the map would go blank.

MapML.js (Leaflet)

The reference implementation. Changing the projection rebuilds the map's coordinate reference system, which is why every layer has to be re-examined afterwards.

MapML-MapLibre

MapLibre is natively Web Mercator, so a non-Mercator projection is a larger undertaking here than in the other two — worth watching on the Lambert button.

MapML-OpenLayers

An OpenLayers View has an immutable projection, so the port builds a new one and re-attaches every layer; centre and zoom are carried across because they are expressed in latitude, longitude and zoom, which no projection owns.

Driving this from buttons is contrived. The same handler is what a real application would use to change projection and data source together in response to a change of map state — see change projection on zoom change, where the trigger is a map-zoom query rather than a click.

The declarative counterpart is <map-layer media="(map-projection: …)">: the same swap, decided by the user agent, with no handler to write and nothing to get out of step. There is also a finer-grained version that gates the individual <map-link rel="tile"> instead.

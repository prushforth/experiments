Theming a basemap by prefers-color-scheme, with matchMedia()

Two styles over one .pmtiles archive, one dark and one light. A (prefers-color-scheme: dark) matcher decides which <map-layer> is in the document, and swaps it on change — so the map follows the colour scheme the reader asked their operating system or browser for, the way the rest of the page does.

Variants Inline only <mapml-viewer> only

MapML.js (Leaflet)

Styled with the protomaps-leaflet rules (application/pmtiles+stylesheet), which is why this column's tile template carries a ?theme= — the rules are keyed by archive URL.

MapML-MapLibre

Styled with a MapLibre style-spec document (application/vnd.maplibre-style+json) — its native format.

MapML-OpenLayers

The same MapLibre style-spec document, compiled to OpenLayers styles. All three columns read the one spearfish.pmtiles archive; only the stylesheet differs.

To see it change, emulate the preference rather than restarting your desktop: in Chrome or Edge, DevTools → More tools → Rendering → Emulate CSS prefers-color-scheme; in Firefox, DevTools settings → Emulate CSS prefers-color-scheme. The frames also honour a system-wide change with no reload.

This is the script-driven counterpart to Dark mode, where the same two layers are declared with media="(prefers-color-scheme: …)" and the user agent chooses. Dark mode is the better answer for a preference this stable; this page exists to show what the handler has to do instead, and to leave the door open for the cases a static attribute cannot cover.

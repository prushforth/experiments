Styling a feature by map-zoom, with matchMedia()

One feature, nineteen colours: the page registers a (map-zoom: n) matcher for every zoom level of the map and rewrites the layer's <map-style> whenever one of them fires change. Zoom the map and the point changes hue. This is the response a media attribute cannot give, because there is no second element to switch to — only a declaration to rewrite.

Mechanism media attribute matchMedia() API

Variants Inline only <mapml-viewer> only

MapML.js (Leaflet)

The reference implementation. Features are SVG elements here, so the rewritten <map-style> reaches them through the ordinary CSS cascade.

MapML-MapLibre

MapLibre paints to a canvas, so the author's CSS is compiled to paint properties; the <map-style> rewrite has to be recompiled on each change.

MapML-OpenLayers

OpenLayers also paints to a canvas; the author's CSS is resolved against a hidden probe element per feature, so the rewritten rule is read back through getComputedStyle and turned into an OpenLayers style.

The matchers are registered once and then left alone — the handler never asks the map for its zoom, it is told. That is the difference between a media query and a zoomend listener that reads state: the query names the condition, and the map decides when it is met.

The declarative counterpart, a stack of <map-link rel="stylesheet" media="(map-zoom: n)">, gets the same result with no script at all — at the price of one stylesheet per zoom level.

Choosing a representation by prefers-map-content, with matchMedia()

The same data — the probability of minimum annual snow and ice over Canada — offered as a WMS image, as tiles, as features, and as a table of descriptions. Press the preference buttons and a handler asks the map, for each <map-layer>, whether its query still matches, and checks or unchecks it accordingly.

MapML.js (Leaflet)

The reference implementation. Every layer is a fetched <map-layer src>, so all five documents are requested here whatever the preference — the handler only decides what to do with them afterwards.

MapML-MapLibre

The preference itself lives in M.options.contentPreference, a global the page writes to — all three implementations read it from the same place.

This dataset is published in CBMTILE, which MapLibre cannot render; it warns and falls back to Web Mercator, so this column shows the preference switching correctly but the geometry in the wrong projection.

MapML-OpenLayers

A matcher's matches is computed when it is made and refreshed on map movement, so a preference change has to be answered with a fresh matcher — which is what the handler does on every click.

Tables is the one preference no map element can satisfy, and the reason this experiment needs the API at all: asking for a table is asking for the map to be replaced, not re-sourced. The handler swaps the map for the year's description table — the same document the msi-tables/ folder holds for every year in the time <map-select>.

The declarative version carries the same five queries in media attributes, and a non-matching remote layer is a document that is never fetched — which matters here more than anywhere else on this site, because four of the five are large.

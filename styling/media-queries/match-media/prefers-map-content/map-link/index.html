Choosing a templated link by prefers-map-content, with matchMedia()

The same experiment as the <map-layer> version, one level finer: a single layer holds one <map-extent> whose templated links offer the data as a WMS GetMap image, as the same request tiled, or as features. The handler disables the links whose query stops matching, so the layer keeps its identity in the layer control while what it draws changes underneath.

MapML.js (Leaflet)

The reference implementation. The time <map-select> is shared by every template, so the year stays put as the representation changes.

MapML-MapLibre

A disabled link leaves the extent's bounds as well as the map, so the layer's reported extent follows the preference as well as its drawing does.

This dataset is published in CBMTILE, which MapLibre cannot render; it warns and falls back to Web Mercator.

MapML-OpenLayers

Disabling a link tears down its template variables and its sub-layer; re-enabling rebuilds them, which is why the tiled and untiled versions of the same WMS request can share one extent without interfering.

This is the shape a real service produces: one layer, one entry in the layer control, and a template per representation of the same data. Gating the whole layer instead is right when the representations are genuinely different products rather than different renderings of one.

Tables is again the preference no map element can satisfy — the original experiment left a <map-link rel=""> commented out precisely because nobody knew what rel a table would have. The handler substitutes the year's description table for the map.

The declarative version puts the same queries in media attributes and needs no handler for anything but the table.

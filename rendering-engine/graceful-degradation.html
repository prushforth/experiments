Graceful degradation

Identical <mapml-viewer> markup rendered by the MapLibre GL build (left) and the Leaflet build (right). Each map runs in its own iframe because both engines register the same custom-element names. An engine that cannot honour what the markup asks for still draws the content, the way a browser ignores an attribute it does not understand.

See also: progressive enhancement, globe view

A globe that degrades to a flat map

Both maps load the same OpenStreetMap raster tiles in projection="OSMTILE", and both ask for view="globe". MapML-MapLibre draws the tiles on a globe. MapML.js has no 3-D renderer and does not know the view attribute, so it ignores it and draws a flat Web Mercator map. The degradation is a property of the markup, not something either engine does: lat, lon and zoom mean the same thing in every view, so the flat map opens on the same place, and view never changes how the layer itself is read.

Compare the Arctic in the two panes. On the globe, Canada's islands keep their shape; on the flat map Web Mercator stretches them the further north they are. The view button (MapLibre only) cycles the left map through globe, perspective and flat; MapML.js skips the view token in controlslist it does not recognise.

Experiments

Localization of map UI, declared inline

A map is chrome as much as it is content: zoom buttons, a layer control, a context menu, a search box, an opacity slider, and the words a screen reader reads out of all of them. None of that is in the page's markup, so none of it can be translated by translating the page. These three maps are in Ukrainian — a document that says <html lang="uk"> and hands the library a table of Ukrainian strings through <map-options>.

Feature tags

Content type Inline Remote
Root element <mapml-viewer> <map is="web-map">

MapML.js (Leaflet)

The reference implementation reads <map-options> out of <head> exactly once, as the library initializes, and merges it over M.options. The viewer then asks itself whether it matches :lang(fr) or :lang(en) — only those two are bundled — and lang="uk" matches neither, so it falls through to the page's table.

MapML-MapLibre

Same language, different source: this implementation bundles Ukrainian alongside English, French, Japanese and Swedish, so :lang(uk) matches a built-in and the page's <map-options> is never consulted here. Worth knowing before concluding that a partial table "worked" — the missing keys would have come from the bundle, not from the page.

MapML-OpenLayers

The same two-step as MapML.js, ported: :lang() first, the page's table as the fallback. One viewer implementation serves both root elements, so whatever these strings do here they also do in the <map is="web-map"> variant.

What to try

  • Each map starts static. Release the lock first — its own button is one of the strings being translated (btnStatic), and while the map is locked it does not take keyboard pan and zoom either.
  • Open the layer control. The layer is named by its label attribute, which is page content and always was translatable; its sub-layer is not named by the page at all, so the control has to call it something — dfExtent, "Підтип шару".
  • Open each of the three context menus: on the map, on the layer, and on the sub-layer. That is the largest block of chrome text a map has, and none of it is in the DOM until you ask for it.
  • Hover the zoom buttons, the reload button, the fullscreen button and the search box for their tooltips; they are the same strings a screen reader announces as accessible names.
  • Search for somewhere — Київ, Львів, Одеса. The placeholder, the close button and the "no name" label for an unnamed result are all localized; the results themselves come from the gazetteer and are in whatever language it returns.
  • Look for the bits that are still English. All three leave the layer control's own toggle button ("Layers") and the scale bar's reading ("0.8 centimeters to 100 kilometers") untranslated — there is no key for either in the table. MapML.js also labels its reload button aria-label="Reload" over the localized tooltip, and names the map landmark "Interactive map"; MapML-MapLibre names it "Map". A screen reader user gets those in English whatever the page says.
  • Compare with the remote variant, where the layer's name arrives from its own document rather than from the page.

<map-options> is not part of the MapML vocabulary; it is how these implementations let a page set M.options before any map is built. It has to be created by script and appended to <head>, because the HTML parser moves unknown elements written in <head> out into the body — where nothing looks for it. A standard version of this would more likely negotiate the language with the user's browser than have the author state it.

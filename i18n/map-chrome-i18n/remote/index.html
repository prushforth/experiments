Localization of map UI, from remote MapML

The page now says only <map-layer src="un-clearmap.mapml">, and the layer's name in the control is no longer a label the page wrote — it is the <map-title> of the fetched document. So the text of a map splits in two: the chrome, which the library supplies and the page localizes with <map-options>, and the content, which the server supplies and can therefore negotiate.

MapML.js (Leaflet)

The layer control builds its label from <map-title> if the document has one, and from the locale's dfLayer — "Шар" — if it does not. Delete the title from the document and the control still names the layer, just less usefully.

MapML-MapLibre

The fetched document lives in the layer's shadow root, a different one from the viewer's, and the control has to look into it for the title. The chrome around that title comes from this implementation's own bundled Ukrainian rather than from the page's table.

MapML-OpenLayers

The sub-layer inside the fetched document is unnamed on purpose, so the two sources of text sit next to each other in one control: a Ukrainian title from the server, and a Ukrainian dfExtent from the page's table.

What to try

  • Open the layer control and compare it with the inline variant. The chrome is identical; only where the layer's name came from has changed.
  • Open the layer's context menu and the sub-layer's. Every item in them is chrome, so this is the part of a map a server cannot localize for you however good its content negotiation is.
  • View the source of un-clearmap.mapml. The attribution and the search service travel with the layer too, so a layer arrives already named, already credited, and already searchable.
  • Release the static lock, then search for Харків or Чернівці.

These three documents are byte-identical copies, one per implementation folder, so that each frame fetches a same-origin document of its own and nothing is shared but the idea.
